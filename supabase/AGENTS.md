# Backend rules

- Commercial billing lives in database functions (issuing, fulfilment, capacity) plus edge functions for IntesaPay and desktop licences; prices are computed server-side from shared modules, report output locks are always enforced (`enforcement_enabled` now only governs capacity limits), and scenario checks in `scripts/billing-scenarios.sql` always roll back.
- Report generation and preview never bill; `billing_unlock_report_output` is the single download/print gate (feature switches, then `billing__issue`), so Learners are charged once per unique card on first output and active desktop licences count as paid.
- Feature switches live in `platform_features` (global) and `school_feature_overrides` (school wins); `feature_guard` triggers refuse writes for switched-off features without touching existing rows, and skip calls without a signed-in user (background jobs).
- Paid access is per term: subscription triggers write `school_term_entitlements` (one row per school/year/term, never deleted, revoked only when the subscription is cancelled) and `billing__issue` unlocks only rows found there, so expired packages keep their paid terms and new packages never widen or narrow other terms.
- Manual payments run order (edge function, server pricing) → proof → super-admin approval (single-use hashed key) → `billing_activate_key`; the database enforces one open request per school (partial unique index) and `billing__package_conflict` blocks overlapping packages at order, approval and activation.
