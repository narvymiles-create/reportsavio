# Architecture rules

- Pre-activation tests use the shared custom PDF pipeline and explicit year context without mutating terms; database-validated association checks and configuration fingerprints gate activation, while missing values only warn. Inactive template corrections reuse Fields Management in an explicitly scoped test dialog to keep defaults read-only.

- Optional school templates use private report-templates storage and atomic school/level selection; active alternatives share PDF bytes across preview/print/download while defaults retain their existing renderers. Custom fields use independent level-scoped definitions and contextual values with validated associations; archive definitions and cascade only associations on template removal to retain historical values. Supported AcroForm fields preserve their standard fonts (Helvetica only as fallback so matched fields never render blank); each template field and each system field may be matched once per template (DB unique indexes); static placements use top-left PDF-point rectangles and fit text without erasing or reflowing artwork.
- Template management remounts its form/list on school or sidebar-level changes; uploads use a server-validated current-level RPC and immutable school/level/file scope. Default previews call the existing default renderers directly, bypassing active alternatives.
- Sidebar selections are cached per school and writes serialized; template uploads await and verify the saved level before storage and registration to avoid stale-level races.
- Template uploads normalize local images to fixed PDFs using pdf-lib without rasterizing PDF inputs; preserve image pixels, aspect ratio and resolution metadata, and keep all report rendering on stored PDF bytes. Normalize plain-object service errors at the upload boundary.

- Academic years are school-scoped independent settings; database triggers project the current year onto the compatibility `terms.year` field so every existing selector and report renderer uses it without changing report artwork or marks identities. Current-year switches are atomic and admin-authorized.

- Primary marksheet summary tables render in `MarksFormPage` from its existing grading bands and computed summary data; keep the 80/20 summary arrangement in shared screen/export/print CSS so layout changes do not alter calculations or report-card PDF generation.
- Primary marksheet print and PDF use the same measured static page DOM from `marksheetOutput`; reserve configured scale/footer height on every page and keep both summaries together on the final page to avoid canvas slicing through learner rows.
- Mount the Primary marksheet's landscape print-page rule with the sheet, after globally imported report styles, and hide sidebar spacer ancestors only when a marksheet is present; this avoids portrait page-rule collisions without changing Nursery or report print styles.

- Primary learner previews use PDF.js in `PrimaryPdfViewer` to read the existing download bytes; printing opens those exact bytes in a native Chrome PDF tab because iframe load events cannot establish native plugin print readiness.
- Primary PDF URL sessions outlive previews while native PDF tabs remain open; revoke only after the preview and all tracked tabs close to avoid interrupting printing.
- Bulk Primary printing copies and validates complete one-page A4 PDFs without transforming artwork; download geometry and grading remain authoritative.
- Legacy report CSS is retained only for the existing settings overlay illustrations; Nursery rendering and print styles remain independent and must not be changed for Primary fixes.- Uploaded templates take values from the default loaders (`customReportData`) and receive Settings stamp/watermark plus an opt-in per-level border (`template_border_<level>`) via `template/decorations.ts`, scaled proportionally to the page; previews refresh on the `REPORT_TEMPLATE_CHANGED` window event.
- Uploaded templates are filled by rule-based section recognition (`templateSections.ts`: label dictionary + Primary/Nursery section registry mirroring the default cards); table rows bind to configured subjects/learning areas in sort order with values from `customReportData`, and recognition overrides legacy one-by-one associations. Per-template corrections (uncertain tables, headings, scanned table positions) live in `report_templates.section_map`, so changing them invalidates verification via the configuration hash.
- Primary marks-entry availability derives from the active uploaded template's recognised exam sections (`useTemplateExams`); without a template, or when none are recognised, all exams stay open, and stored marks are never deleted. Learner registration numbers are independent columns with `active_reg_types` listing the active ones (`active_reg_type` kept as the first for existing renderers).
